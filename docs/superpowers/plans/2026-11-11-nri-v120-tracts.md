# NRI v1.20 county and tract projections implementation plan

**Goal:** Generate reproducible drought, wildfire and LOCA2 heat projections using NRI v1.20 at county-equivalent and tract levels, including Connecticut's nine planning regions.

**Architecture:** Keep the December 2024 archive, its regression tests, and existing released analyses immutable. Add a versioned v1.20 Hamilton calculation that reuses the verified MME50 climate snapshot, builds overlap weights for current county/tract geometries, refits wildfire elasticity at county level, and scores each national geography separately. Store review outputs under the existing results collection as `fri/counties/<version>` and `fri/tracts/<version>` with baseline/source/weight provenance. Do not activate an approved release or copy to staging automatically.

**Tech stack:** Existing Python, Apache Hamilton, GeoPandas/Shapely, SciPy sparse arrays, Google Cloud Batch, GCS, PMTiles and React.

## Tasks

- [ ] Verify existing pipeline tests before changes. Create an isolated feature worktree.
- [ ] Add failing tests for version detection, HWAV-to-EXHT field mapping, new CT IDs, missing-value preservation, matching tract IDs, geometry-specific thresholds, and fixed county-fitted wildfire elasticity for tract calculation.
- [ ] Implement a v1.20 baseline/geography loader with explicit source hashes. Download official NRI county and tract tables and 2024 Census boundary files; reject version/ID mismatches and preserve all source inventories.
- [ ] Build sparse overlaps against the exact saved climate cell coordinates. Retain 0.25-degree support explicitly; small tract polygons do not increase climate resolution. Check every CONUS area has finite climate support.
- [ ] Run Hamilton hazard calculations over county and tract weights; fit gamma only against county wildfire losses and fuel shares. Rank the complete national county and tract populations separately, preserve NRI missing/not-applicable statuses, and derive bins from the matching v1.20 baseline rather than archive bins.
- [ ] Package immutable GeoParquet and reproducibility artifacts plus a comparison report. Use the existing experiments/results buckets. Store county and tract files behind their own version directories in the same FRI dataset; include native NRI inputs as a separate dataset.
- [ ] Add a bounded Batch launcher and on-demand workflow for the new calculation, with snapshot hash, image digest, version, private network, and output identity pinned. Keep publication approval separate.
- [ ] Run tests/lint, build an immutable worker, submit the real job to Batch, inspect errors and validate completed outputs. No large climate calculation on the laptop.
- [ ] Update the combined review interface with the new county baseline and optional tract selection once verified assets exist. Keep original archive and older analyses intact; use release-specific bin data and baseline labels. Tract context must not reuse a county narrative as a tract claim.
- [ ] Review diff, push branch, create a review PR, confirm preview and report concrete results/limitations.

## Validation

Use independent synthetic fixtures to show tract-specific baseline loss changes output even with identical climate multipliers, and that tract ranks/bins do not use county populations. Run the existing archive regression unchanged (310,176 comparisons). Validate the real output's FIPS/GEOIDs, CT nine-region identity, native baseline counts and null masks, all 16 multiplier columns, finite support, >=1 floor contract, GeoParquet round trips, source hashes, and sampled PMTiles attributes. Record county vs archive and tract vs county summaries as reconstruction/baseline differences, not observed temporal changes.
